# Симптомы и границы мобильной проверки

Выбирай строки по конкретному интерфейсу. Рецепт — кандидат, а не доказательство
сбоя или правило менять все сайты. Сначала проверь существующие компоненты.

| Симптом или риск | Возможное действие в implementation | Что ещё проверить |
| --- | --- | --- |
| Hover меняет размер/доступность на touch | Ограничить hover по `(hover: hover)` и при необходимости `(pointer: fine)`; оставить доступную обычную/active/focus подачу | Hybrid-ввод, touch и работа действия без hover |
| При фокусе мелкого input страница приближается | Проверить вычисленный шрифт ввода; для целевого iOS часто нужен минимум 16 CSS px | Фокус и экранная клавиатура на целевом устройстве; zoom страницы не отключать |
| Полноэкранная оболочка теряет низ | Оценить `dvh` для динамической оболочки, `svh` для стабильной начальной секции; fallback по матрице поддержки | Изменение browser chrome, ориентация, клавиатура; фиксированный viewport это не моделирует |
| Фиксированная кнопка попадает под системную область | При edge-to-edge оценить viewport-fit и padding через `env(safe-area-inset-*, 0px)` | Физическое устройство и целевой веб/PWA; нулевой inset в эмуляции не подтверждает безопасный отступ |
| Жест конфликтует с прокруткой | Выбрать touch-action для конкретной поверхности; нативная прокрутка/scroll snap при возможности | Вертикальный проход страницы, pinch zoom и доступность действия без жеста |
| Вложенный scroll двигает страницу | Оценить локальный `overscroll-behavior: contain` | Обычное чтение, системные жесты и целевые браузеры; не ставить none на весь документ по привычке |
| Убрана системная подсветка нажатия | Сохранить собственную различимую обратную связь, focus и active | Физическое нажатие; не убирать подсказку ради «нативности» без замены |
| Долгое нажатие мешает конкретному контролу | Ограничить user-select только этим контролом, если это действительно нужно | Основной текст, адреса и ошибки остаются копируемыми |
| Browser chrome не соответствует теме | Проверить theme-color для реально поддержанных схем | Не включать dark mode, которого нет в дизайне; standalone проверяется отдельно |

`viewport-fit=cover`, `interactive-widget`, изменение theme-color и PWA-манифеста
не являются обязательным пакетом для обычного лендинга. Сохраняй работающие
браузерные возможности, если у продукта нет причины их менять.

## Минимум доказательств

1. Код: фактическое значение meta/CSS, расположение правил, причина и diff.
2. Браузер: версия, viewport и pointer/hover-условия, фактически пройденный путь,
   ошибки, снимки и их просмотр. Отметь, если тест использует мышь/desktop keyboard.
3. Устройство: только при реальном доступе — модель, ОС, браузер, режим и
   наблюдение. Иначе перечисли конкретные непроверенные пункты и способ проверки.

Сравни обычное и длинное содержание; проверь фокус и переход к действию.
Не превращай успешную клиентскую демонстрацию в заявление о доставке заявки.
