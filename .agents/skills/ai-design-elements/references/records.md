# Реестр решений по элементам

По умолчанию `design/ELEMENTS.json`; существующий эквивалент имеет приоритет.
Для маленькой правки те же сведения можно кратко сохранить в IMPLEMENTATION/REVIEW.
Реестр содержит ссылки и результаты, не копии чужого исходного кода.

```bash
python3 "$SKILL/scripts/elements.py" new --id contact-form --task "Связаться с автором" --out design/ELEMENTS.json
python3 "$SKILL/scripts/elements.py" check design/ELEMENTS.json --project-version snapshot-02
```

`new` создаёт один черновик в новом файле; родительский каталог должен существовать.
Существующий файл или симлинк не перезаписывается. Для добавления следующих
элементов добавь запись в `components` обычным редактированием. В review черновик
создаётся только в разрешённом каталоге отчёта, не в исходниках продукта.

Формат корня: `schema_version: "1.0"`, `components: [...]`.
Неизвестные поля считаются ошибкой, чтобы опечатка не скрыла проверку.
`new` даёт полный образец полей и начальных значений.

| Поле записи | Значение |
| --- | --- |
| id, task, mode | Уникальный ID, задача и selection/implementation/review |
| project_version, design_reference | Коммит/контрольная сумма/устойчивый снимок и действующее основание дизайна |
| existing | path, decision (reuse/adapt/replace/none), reason; чем обоснован выбор |
| source | kind (local/native/external), url (в т.ч. путь), revision, files (список), inspected (bool), license |
| source.license | name, evidence (URL/путь), checked_on (YYYY-MM-DD), usage (site/redistribution), rights (confirmed/unknown/denied), notice (место notices либо обоснованная неприменимость) |
| dependencies | items (точные версии либо пустой список), primitive_base (или none), reviewed (bool), compatibility (confirmed/unknown/incompatible), evidence |
| adaptation | Соответствие токенам/типографике/состояниям и обоснование движения, либо ссылка на действующую реализацию |
| checks | Массив: area, status, version, environment, evidence, reason |

Области checks: functional, accessibility, responsive, performance, visual.
Несколько проверок области допустимы: например, axe и ручная клавиатура
записываются раздельно. `pass` требует версию, среду и путь/ссылку на доказательство;
`not-applicable` — причину и версию. `fail` сохраняет причину или доказательство.
`not-checked` сохраняет пробел. В accessibility укажи применимые zoom/reflow,
клавиатуру, focus, touch, reduced-motion; один axe не закрывает ручную часть.
Содержимое и достаточность доказательств проверяет агент, CLI их не читает.

## Статусы CLI

`check` проверяет структуру и вычисляет статус **по записанным сведениям**.
Поля `approved` нет: наличие заполненного JSON не означает одобрение владельцем.

- `candidate`: не заполнены проектное основание, источник/его просмотр, права,
  notices, зависимости, совместимость или адаптация; указаны недостающие условия.
- `blocked`: записан прямой запрет нужного использования или несовместимость.
- `needs-work`: есть записанная проваленная проверка текущей версии.
- `ready-to-adapt`: условия отбора записаны, но проверка в интерфейсе неполна
  или относится к другой версии. Это не разрешение на запись при подборе/ревью.
- `verified-record`: все пять областей текущей версии имеют pass или обоснованное
  not-applicable, и нет других открытых/устаревших проверок. Это полнота записи,
  не доказательство фактического прохождения тестов или визуальной приёмки.

`--project-version` обязателен: передай фактическую текущую версию, не подгоняй
её под прошлый отчёт. Расхождение с `project_version` и устаревшие checks сохраняют
проверку открытой. При переносе в другой проект повтори применимые проверки;
версия должна однозначно определять проект и результат, например commit + путь.

Для local/native права не угадываются из места хранения: если происхождение
унаследовано, `license.evidence` ссылается на реестр/notices проекта. Для собственного
нативного решения укажи происхождение и обоснованную неприменимость notices.
Для external лицензия и source.url должны ссылаться на HTTP(S) первоисточник.

Записывай точную версию/коммит или устойчивый снимок. CLI отклоняет известные
плавающие обозначения (`latest`, `main`, `HEAD`, диапазоны `^`/`~`/`*` и подобные)
как незавершённый отбор; это не проверка существования или неизменности произвольной
строки. При смене исходника/способа использования заново проверь права, notices
и зависимые доказательства; `confirmed` нельзя механически переносить с сайта
на распространение библиотеки. Секреты и ключи в реестр не записываются.

Код выхода: 0 — все записи verified-record; 1 — корректный реестр, но есть
открытые условия; 2 — ошибка формата/файла/аргументов. Пустой реестр не является
успешной приёмкой. Команда ничего не устанавливает и не меняет реестр.
