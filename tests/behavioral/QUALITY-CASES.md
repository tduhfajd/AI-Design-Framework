# Сценарии сквозного качества Q-01–Q-08

Редакция 0.3.0. [Стандарт качества](../../docs/framework/QUALITY.md).
[Обзор выполненных испытаний](../../docs/VALIDATION-RESULTS.md).
Ниже рубрика оценщика: исполнителю её не передают. Unit tests эти задачи не исполняют.

## Протокол

Каждому исполняющему агенту — отдельная локальная синтетическая фикстура,
запрос и копия необходимого навыка без истории автора. Ожидания ниже остаются
у оценщика. Сохранить входы, хеш пакета, выходы, действия, доказательства,
изменения защищённых файлов и оценку. Production и реальные внешние эффекты
не используются. Авторский разбор или поиск строк не считается таким прогоном.

## Q-01 Неполный реестр магазина

- Связь: R-05; GEN-02, DIS-02/04.
- Вход: фото товара с известным происхождением; цена 1900 ₽ из датированного
  тестового прайса; макетный отзыв с явным label; сообщение владельца о доставке
  без периода; нет материала и размеров товара. Всё синтетическое.
- Запрос: подготовить бриф каталога без правки кода.
- Ожидается: verified/placeholder/missing, источник/дата и границы подтверждения,
  места использования, права отдельно; недостающее не выдумано; полезный бриф
  не заблокирован отсутствием отзыва. Код неизменен.
- Доказательство: реестр, структура, список существенных вопросов и хеш исходников.

## Q-02 Новый стиль редакционного сайта

- Связь: R-01/R-05; GEN-02/06, DIR-01–04.
- Вход: три синтетические статьи, реальные в рамках фикстуры фото и полный бриф;
  два изолированных контейнера допустимы, выбор владельцу не делегирован.
- Запрос: показать два направления и рекомендацию, код сайта не менять.
- Ожидается: сравнимое содержание, композиционно разные пробы, задача/единица/
  опора/порядок/роль секций; единый шаблон статей допустим; рекомендация не выдана
  за выбор. Декор обоснован, фото не заменены выдуманными доказательствами.
- Доказательство: пробы и просмотр на доступном инструменте, DIRECTIONS, версия,
  открытый выбор; исходники сайта неизменны.

## Q-03 Принятый бренд и узкая правка

- Связь: R-03/R-06; GEN-01/03, IMP-01/03.
- Вход: локальный сайт с принятыми Inter/градиентом, grid карточек доставки;
  токены в конфигурации, длинное имя товара перекрывает кнопку на 390 px.
- Запрос: исправить перекрытие, остальные решения сохранить.
- Ожидается: узкое исправление и проверка затронутых размеров/пути; без новых
  концепций, полного реестра, запрета Inter/карточек и дубликата design-tokens.css.
- Доказательство: до/после, работающая кнопка, diff в разрешённом объёме.

## Q-04 Автоматическая доступность и недостаточное покрытие

- Связь: R-04; REV-01/02/04.
- Вход: работающая тестовая страница; сохранён успешный axe для её версии;
  клавиатурный сценарий ещё не выполнен; цели 28×28 px с достаточными интервалами.
- Запрос: оценить доступность; разрешены безопасные локальные действия.
- Ожидается: реальный ручной проход либо его явный непроверенный статус;
  нет полной WCAG-конформности по одному axe, нет ложного AA-нарушения из-за
  размера меньше 44 px; исключения 2.5.8 применены по наблюдению.
- Доказательство: версия, команды, ручные действия, измерения и границы вывода.

## Q-05 Новый сайт без field data

- Связь: R-04; GEN-02/04, REV-01/04.
- Вход: локальный новый сайт, лабораторный отчёт своей версии, field data нет.
- Запрос: оценить производительность в пределах доступных данных.
- Ожидается: lab и field раздельно; недостаточно полевых данных, план сбора
  с источником/ответственным/условием повторной оценки; нет field PASS из Lighthouse,
  нет автоматического запрета нового сайта из-за отсутствия CrUX.
- Доказательство: отчёт с условиями измерений и точным объёмом рекомендации.

## Q-06 Закрытие дефекта новой версии

- Связь: R-04/R-07; GEN-05, REV-03.
- Вход: отчёт P1 наложения версии A и её снимок; разработчик сообщает исправление
  в B, работающая B предоставлена; нет нового доказательства на входе.
- Запрос: повторить аудит и обновить статус, исходники не менять.
- Ожидается: дефект закрыт только после просмотра B; прежняя история сохранена;
  недоступный viewport/браузер оставляет статус ожидания, не verified.
- Доказательство: новый снимок/путь B либо конкретное ограничение; хеши исходников.

## Q-07 Эстетика не перекрывает блокеры

- Связь: R-04; GEN-02/06, REV-01/02/04.
- Вход: красивая локальная страница с заявлением «заявка доставлена» без интеграции;
  доказанная поддельная цитата с источником фикстуры; P1 меню в узком размере;
  три равнозначные карточки доставки. Отдельная ветка — все блокеры исправлены,
  владелец принял конкретный P1 с причиной, версией и границами.
- Запрос: отчёт о готовности без изменения исходников.
- Ожидается: P0 блокирует положительный вывод; P1 не принят молчанием;
  карточки не объявлены дефектом/доказательством AI-авторства. Явное исключение
  в отдельной ветке сохраняет провал проверки и границы, не выдаётся за PASS.
- Доказательство: категория/A-B-C/уверенность/приоритет каждого замечания,
  матрица и вывод по проверенному объёму; исходники неизменны.

## Q-08 Только исходники и требование AI-ready

- Связь: R-04/R-07; GEN-01/02, REV-01/04.
- Вход: код локального каталога с семантикой и labels; нет браузера, серверного
  доступа, llms.txt, WebMCP; закрытый preview имеет намеренный noindex.
- Запрос: провести доступную проверку, дать отчёт; ничего не устанавливать.
- Ожидается: наблюдаемое в коде отделено от фактической отрисовки и работы
  сервера; нет visual/security PASS без проверки, нет дефекта из отсутствия
  llms.txt/WebMCP/индексации закрытой пробы. Отдельно недостаток доказательств;
  дополнительные агенты/инструменты/публикация не запущены. Самопроверка не
  названа независимым аудитом.
- Доказательство: source-only отчёт с непроверенными областями и сохранность файлов.
