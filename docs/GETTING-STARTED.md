# Подключение к своему сайту

## Что понадобится

- Codex с локальными Agent Skills либо агент, которому вы вручную передадите нужный `SKILL.md`.
- Каталог целевого сайта и разрешённая область работы.
- Python 3.10+ для установщика; при ручном копировании он не нужен.
- Для визуальной проверки — доступный браузер или изображения. При переносе в CMS —
  разрешённая тестовая CMS с реальным редактором.

Скилы не устанавливают Node, браузер, Docker, WordPress, MCP или платные сервисы.
Выбирайте среду и инструменты под свой проект. Figma необязательна.

## С установщиком

Скачайте репозиторий через Git или GitHub Download ZIP, распакуйте и перейдите в его корень.
Для ZIP путь к скрипту и поведение те же.

```sh
python3 scripts/install.py --project /path/to/site --dry-run
python3 scripts/install.py --project /path/to/site
```

Установка одного пакета:

```sh
python3 scripts/install.py --project /path/to/site --skills ai-design-review
```

По умолчанию устанавливаются все семь пакетов. Основные четыре этапа и один review самодостаточны; отсутствие
специализации не разрешает ему менять исходники и не обязывает устанавливать весь набор.

Установщик проверяет все выбранные назначения до записи. При отличающихся существующих
файлах он завершится с ошибкой. Сравните версии, сохраните свою копию **за пределами
обнаруживаемого каталога skills**, затем замените согласованные пакеты вручную.
Флага принудительной перезаписи нет. При сбое файловой системы возможен частично
скопированный набор полных папок; повторный запуск пропустит уже совпадающие пакеты.

Повторная установка той же версии ничего не меняет. Символические ссылки в назначении
установщик отклоняет, чтобы не записать файлы в другой каталог неожиданно.

## Вручную

Скопируйте нужные каталоги из `.agents/skills/` этого репозитория в `.agents/skills/`
проекта сайта. Сохраняйте пакет целиком: `SKILL.md`, `agents`, `assets`, `references`,
а у элементов также `scripts`, `resources`, `SOURCE.md`, у адаптаций — `LICENSE`
и `SOURCE.md`. Сначала сравните уже существующие пакеты. Служебные `__pycache__`
и bytecode не копируйте; установщик исключает их автоматически.

Откройте целевой проект в Codex и проверьте доступность skills. Codex поддерживает
репозиторные `.agents/skills`; при отсутствии обновления списка перезапустите приложение.
Поведение обнаружения сверено 15 октября 2026 с
[официальной документацией OpenAI](https://learn.chatgpt.com/docs/build-skills)
и [примером использования в OSS](https://developers.openai.com/blog/skills-agents-sdk).
Подключение в других клиентах зависит от их собственных правил.

## AGENTS.md и документы дизайна

`AGENTS.md` в корне **этого** репозитория предназначен для разработчиков фреймворка.
В проект сайта можно вручную добавить [AGENTS.addendum.md](AGENTS.addendum.md),
сохранив существующие правила стека и команды. Установщик этот файл не трогает.

Заранее создавать все `design/*.md` не нужно. Агент создаёт результаты нужного
этапа по вложенным шаблонам. Существующий бриф или утверждённый макет можно использовать
как основание без дублирования. При установке через ZIP включите показ скрытых файлов,
чтобы увидеть `.agents`.

## Первый проход

Для нового сайта начните с discovery: задача, аудитория, настоящее содержание,
основной путь и ограничения. Затем direction готовит сравнимые пробы. Выберите
направление или явно делегируйте выбор, после чего поручите реализацию.

```text
Выбираю направление «Редакционное». Сохрани решение и примени
$ai-design-implementation. Реализуй выбранный дизайн в локальном проекте:
сначала проверь представительную страницу, затем продолжи согласованный объём.
Техническое принятие пилота делегирую тебе. Публикация не входит в задачу.
```

После реализации:

```text
Используй $ai-design-review. Проверь реальный локальный сайт по адресу,
указанному в design/IMPLEMENTATION.md: мобильный и настольный размеры,
основной путь и явные требования design/DESIGN.md. Код не меняй.
Сохрани отчёт и доказательства; отдельно укажи фактически просмотренные экраны.
```

Для локальной правки или готового макета используйте
[короткий маршрут](framework/ROUTES.md). Новый полный бриф и варианты стиля в таких
задачах часто не нужны. [Примеры запросов](EXAMPLES.md).

## Отдельная установка элементов

Для нового навыка отдельно:

```sh
python3 scripts/install.py --project /path/to/site --skills ai-design-elements --dry-run
python3 scripts/install.py --project /path/to/site --skills ai-design-elements
```

После установки:

```text
Используй $ai-design-elements: подбери форму связи под действующий дизайн сайта.
Сначала проверь существующие компоненты. Сохрани выбор и ограничения;
код и зависимости пока не меняй.
```

CLI доступен по пути `.agents/skills/ai-design-elements/scripts/elements.py`
в проекте сайта. Ему нужен Python 3.10+, сторонние зависимости и MCP не нужны.
[Команды и режимы](framework/ELEMENTS.md). При обновлении с 0.3.0 сравните также
изменённые direction/implementation/review: они подключают новый навык при доступности.
Установка только elements не обновляет другие пакеты автоматически.

## Если что-то не работает

| Ситуация | Действие |
| --- | --- |
| Скил не виден | Проверьте каталог `.agents/skills/<name>/SKILL.md` внутри открытого проекта; перезапустите Codex |
| Есть два скила с одинаковым именем | Проверьте репозиторные и пользовательские установки; оставьте нужный источник, сравнив версии |
| Установщик сообщает конфликт | Сравните существующие файлы и сохраните свои изменения; принудительной замены нет |
| Нет браузера | Допустим частичный отчёт по коду; визуальная проверка остаётся открытой |
| Есть только скриншот | Можно оценить видимое, взаимодействия остаются непроверенными |
| CMS недоступна | HTML-проба остаётся полезной, редактор и реальные CMS-маршруты не объявляются проверенными |
| Агент меняет код при review | Зафиксируйте нарушение объёма; сравните изменения и восстановите собственные файлы осознанно, без общего сброса |
