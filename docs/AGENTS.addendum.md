# Правила дизайна для проекта сайта

Дополнение для ручного включения в существующий AGENTS.md. Сохраните правила проекта.

- Для нового сайта или смены задачи применяй `ai-design-discovery`; для выбора стиля —
  `ai-design-direction`; для реализации принятого решения — `ai-design-implementation`;
  для проверки отрисованного результата — `ai-design-review`.
- Перед работой прочитай существующие дизайн-документы и решения владельца.
  Храни визуальные решения проекта в `design/DESIGN.md` или его действующем эквиваленте.
- Проверяй применимые явные требования по реальным экранам. Рекомендацию,
  делегированный выбор и приёмку владельцем записывай раздельно.
- В review сохраняй исходники продукта. Исправления выполняй в разрешённом объёме
  implementation и подтверждай новой проверкой.
- Крайние данные проверяй через `break-ui`, мобильные симптомы — через `mobile-native`,
  если эти пакеты доступны. Область записи задаёт основная задача.
- Перед передачей укажи версию, запуск, фактически выполненные действия,
  просмотренные изображения и непроверенное. Viewport не заменяет физический телефон;
  успешная форма не доказывает доставку или оплату.

- Ссылки и кнопки оформляй ясными текстовыми подписями без декоративных стрелок,
  в том числе SVG, иконок и CSS-псевдоэлементов при hover/focus.

- Существенные факты и материалы связывай с источником/датой и статусом
  verified/placeholder/missing; неизвестные сведения оставляй явным пробелом.
- В review разделяй требование A, UX-эвристику B и эстетическую гипотезу C;
  категория, уверенность и P0/P1/P2 — отдельные поля. Итоговая матрица относится
  к фактически проверенному объёму; lab/field, автоматическая/ручная доступность
  и приёмка владельца различаются.
