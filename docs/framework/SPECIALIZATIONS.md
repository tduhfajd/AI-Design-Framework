# Специализации работы с интерфейсом

Дополнение 19 октября 2026 после 0.3.0: [ai-design-elements](ELEMENTS.md)
для подбора, адаптации и проверки элементов с каталогом источников и реестром
решений. Используется внутри существующих этапов; не требует React или MCP.
Разделы ниже сохраняют контракты двух ранее добавленных специализаций.

Дополнение к редакции 0.2 от 15 октября 2026 года. Четыре основных этапа и
22 основных критерия сохраняются; ниже восемь дополнительных критериев
профилей break-ui/mobile-native, условия элементов описаны в ELEMENTS.
Источник — [происхождение адаптаций](../../CREDITS.md).
Подключены локальные адаптации, а не неизменённые upstream-пакеты.

## Выбор и действия

| Запрос | Основной этап | Специализация и допустимые действия |
| --- | --- | --- |
| Проверить компонент на крайних данных, не исправлять | review, R-04 | break-ui: карта полей, данные, просмотр; стенд только вне исходников, если разрешён |
| Подготовить dev-стенд без исправления компонента | implementation, R-06 | break-ui: фикстуры и переключатель в заданном тестовом месте; компонент неизменен |
| Найти и исправить проблемы крайних данных | implementation → review, R-03 | break-ui: сначала доказательство, затем разрешённые изменения, повторный проход крайних и обычных данных |
| Проверить мобильный веб без изменений | review, R-04 | mobile-native: код и доступный браузер, матрица доказательств, аппаратные ограничения |
| Исправить конкретную мобильную проблему | implementation → review, R-03 | mobile-native: минимальная CSS/HTML/JS-правка, доступный повторный проход; проверка телефона отдельно |
| Продолжить после изменения данных или устройства | R-07 | Проверить новую версию и зависимые утверждения; старое доказательство сохранить как историю |

Основной этап задаёт режим специализации. Ни имя внешнего навыка, ни dev-only
характер изменения не разрешают запись в исходники при аудите. В запросе на
проверку допустим отдельный стенд для доказательств, если его запись разрешена;
если запрещена любая экспериментальная запись, остаются доступный просмотр
и анализ рисков с ограничениями. Исправление уже разрешённого объёма не требует
повторного разрешения. Неоднозначные продуктовые решения отделяются от дефектов.

## Дополнительные контракты

| ID | Проверяемое условие |
| --- | --- |
| BU-01 | Значения связаны с реальными полями/схемой или обоснованным примером; поступают через действующую границу того же компонента. Неизвестный предел не объявлен отсутствующим. |
| BU-02 | Режим и область записи явны. В review продукт неизменен, стенд отделён; в implementation изменён только разрешённый объём. |
| BU-03 | Наборы, версии, размеры, просмотр и ограничения сохранены. Предположение по коду не названо визуальным дефектом; неприменимое объяснено. |
| BU-04 | При исправлении повторены крайние и обычные данные, затронутый путь. При аудите без исправления повторный проход неприменим с причиной. |
| MN-01 | Мобильные проверки и изменения выбраны по симптому и типу сайта; универсальный native-baseline не навязан документу. |
| MN-02 | Соблюдены режим и границы; сохраняются zoom, выделение основного текста и доступность действий. |
| MN-03 | Различены код, эмуляция и физическое устройство; наблюдения привязаны к версии и конкретной среде. |
| MN-04 | Исправления повторно проверены в доступной среде; аппаратные пункты без устройства остаются открытыми с протоколом следующей проверки. |

## Артефакты и завершение

Навыки самодостаточны: [break-ui](../../.agents/skills/break-ui/SKILL.md) и
[mobile-native](../../.agents/skills/mobile-native/SKILL.md). Они включают
руководства, метаданные, SOURCE и MIT LICENSE. Четыре основных навыка остаются
работоспособными без этих пакетов; маршрутизация использует их при доступности.
Глобальная установка и остальные 13 upstream-навыков не входят в изменение.

Результаты дополняют REVIEW/IMPLEMENTATION, а не создают обязательный второй
пакет документов. Записываются режим, пути записи, версия, набор/среда,
наблюдение, доказательство, последствие, действие и ограничения.
В mobile-native дополнительно различаются код, эмуляция и физическое устройство.

Готовый отчёт не означает исправление или приёмку. Без запуска визуальная
проверка частичная. При задаче устранить физический мобильный симптом без
телефона код можно реализовать и проверить в браузере, но эффект на устройстве
остаётся открытым, а общий результат — частичным. Обычный аудит не блокируется
только потому, что телефон недоступен.

Испытания дополнения имеют собственные номера S-01–S-06 в
[VALIDATION.md](VALIDATION.md); они не закрывают автоматически T-01–T-21.
